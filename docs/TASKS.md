# MarketLens · план на один день

Работают три участника. Артур берёт дашборд на себя и собирает релиз. Улан
пока вне текущего распределения. Общая база — опубликованная `origin/feat/core`.
Если рабочая ветка уже есть, продолжайте в ней. Начинайте с P0 своего потока
сразу, используя [контракт v1](DATA_CONTRACT.md).

## Независимые потоки P0

| Ветка и владелец | Задачи | Как проверять самостоятельно |
|---|---|---|
| `feat/parsers` — Алимжан (Алим) | Довести сбор одной категории OLX («Мобильные телефоны») до воспроизводимого экспорта реальных Listing. Сверить три оригинала, цены, уникальность ID, обработку отказов и повторный импорт. Разрешение на сбор подтверждено заказчиком. | Тесты парсера с сохранённым HTML, затем живой сбор и импорт в выделенный эмулятор. Аналитику и UI для этой проверки запускать не требуется. |
| `feat/analytics` — Алинур | Реализовать группировку, рыночную оценку, выгоду, признаки риска и агрегаты с гистограммой. Подготовить точки вызова и результаты `AnalysisResult` / `MarketStats`. | Использовать фиксированный набор маркированных `Listing` из тестов. Проверить малую выборку, выбросы, отсутствующие цены, смешанные валюты и повторный расчёт. Для начала живой OLX и дашборд не нужны. |
| `feat/core` — Артур | Дашборд и график распределения, сравнение цены и представление выгодных предложений. Затем подключить опубликованные парсер и аналитику, проверить импорт, каталог, ссылки, оценку и признаки риска. | Разрабатывать UI на тестовых ответах `ListingPage` / `StatsPage` по контракту. Проверять загрузку, ошибки, пустые состояния и мобильный экран. Использовать отдельные Firebase Auth и Firestore Emulator для проверки API и браузера. |

## Передача результатов и интеграция

1. Каждый участник публикует проверенный коммит в своей ветке и оставляет
   короткую инструкцию запуска, входные данные, формат результата и итоги тестов
   рядом со своим модулем. Алим передаёт команду экспорта. Алинур указывает
   функцию расчёта и как получить оба вида результата.
2. Не ждите чужую ветку для выполнения своей части. Если внешний доступ,
   живые данные или чужой модуль недоступны, доведите собственный модуль
   на контрактных тестах, опубликуйте его и зафиксируйте конкретную проверку,
   которая осталась. Тестовые данные не включайте в реальный каталог.
3. Артур подключает модули по мере публикации. Финальный P0 проверяется на
   живых данных по цепочке OLX → Firestore → каталог → оценка и признаки риска →
   оригинал. Сверить три оригинала, цены, фильтры, группы и отсутствие дублей.
   Сценарий должен работать без Gemini. Перед показом прогнать
   Ruff/pytest, Vitest и сборку.

После подтверждения P0 переходите к P1 по [описанию проекта](PROJECT.md). История
в интерфейсе, Krisha и Kolesa относятся к P2.
